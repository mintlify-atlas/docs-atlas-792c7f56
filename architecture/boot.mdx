aeryk uses the [Limine bootloader](https://github.com/limine-bootloader/limine) to handle the transition from UEFI/BIOS firmware to the kernel. Limine parses the kernel ELF, sets up a linear framebuffer, maps all physical memory into the higher half, and delivers a memory map — leaving `kmain()` free to skip all legacy boot scaffolding and go straight to hardware initialization.

## Limine bootloader overview

Limine implements the Limine boot protocol, a modern specification designed for 64-bit kernels. When the machine powers on, firmware hands control to Limine, which:

1. Parses the kernel ELF binary and loads its segments into memory at the link address (`0xffffffff80000000`).
2. Enables long mode (64-bit) and sets up an identity-plus-HHDM virtual address space.
3. Scans ACPI/UEFI for a physical memory map and passes it to the kernel.
4. Loads any additional modules listed in `limine.conf` (font, initramfs).
5. Locates the kernel's embedded Limine request structures and fills in their `response` pointers.
6. Calls `kmain()`.

aeryk chose Limine because it eliminates a large class of early-boot complexity: the framebuffer is ready before the first line of C runs, modules (font, initramfs) arrive as contiguous memory regions with known addresses, and the Higher Half Direct Map means the PMM can convert physical→virtual addresses with a single addition.

<Note>
  aeryk requires **Limine base revision 6**. The very first thing `kmain()` does after `init_gdt()` and `init_idt()` is check `LIMINE_BASE_REVISION_SUPPORTED(limine_base_revision)`. If the running Limine version does not support revision 6, the kernel calls `hcf()` and halts permanently.
</Note>

## Limine protocol requests

The kernel declares its Limine requests as `static volatile` structures placed in a dedicated `.limine_requests` linker section. Limine scans for the start/end markers (`LIMINE_REQUESTS_START_MARKER`, `LIMINE_REQUESTS_END_MARKER`) and fills each request's `response` pointer before calling `kmain()`.

aeryk uses five requests:

```c
// Revision check — kernel halts if Limine doesn't support revision 6
__attribute__((used, section(".limine_requests")))
static volatile uint64_t limine_base_revision[] = LIMINE_BASE_REVISION(6);

// Linear framebuffer: address, width, height, pitch
__attribute__((used, section(".limine_requests")))
static volatile struct limine_framebuffer_request framebuffer_request = {
    .id = LIMINE_FRAMEBUFFER_REQUEST_ID, .revision = 0
};

// Loaded modules (PSF1 font + initramfs CPIO archive)
__attribute__((used, section(".limine_requests")))
static volatile struct limine_module_request module_request = {
    .id = LIMINE_MODULE_REQUEST_ID, .revision = 0
};

// Physical memory map (usable regions, reserved, ACPI, etc.)
__attribute__((used, section(".limine_requests")))
volatile struct limine_memmap_request memmap_request = {
    .id = LIMINE_MEMMAP_REQUEST_ID, .revision = 0
};

// Higher Half Direct Map offset (physical address → virtual address)
__attribute__((used, section(".limine_requests")))
volatile struct limine_hhdm_request hhdm_request = {
    .id = LIMINE_HHDM_REQUEST_ID, .revision = 0
};
```

| Request | What the kernel gets |
|---------|---------------------|
| `LIMINE_BASE_REVISION(6)` | Confirmation that the bootloader supports the revision the kernel was written against. |
| `framebuffer_request` | `response->framebuffers[0]` — base address, width, height, pitch in bytes, and pixel format. Used by `init_display()` to construct the `FrameBuffer` struct. |
| `module_request` | `response->modules[]` — array of `limine_file*`, each with a `path` string and a `address`/`size` pair for the module data in memory. |
| `memmap_request` | `response->entries[]` — physical memory map. The PMM uses this to find usable regions and calculate the highest available address. |
| `hhdm_request` | `response->offset` — the constant added to any physical address to obtain its HHDM virtual address. Stored globally as `hhdm_offset` in `pmm.c`. |

## Boot configuration

`boot/limine.conf` is the Limine configuration file placed on the EFI System Partition (or boot partition) alongside the kernel binary and modules. aeryk's config is minimal:

```ini
term_palette: 282828;cc241d;98971a;d79921;458588;b16286;689d6a;a89984
term_palette_bright: 928374;fb4934;b8bb26;fabd2f;83a598;d3869b;8ec07c;ebdbb2
term_background: 282828
term_foreground: ebdbb2
term_background_bright: 928374
term_foreground_bright: ebdbb2

timeout: 5

/Aeryk
  protocol: limine
  path: boot():/boot/kernel
  module_path: boot():/boot/cp850-8x16.psf
  module_path: boot():/boot/initramfs.cpio
```

The key fields:

- `protocol: limine` — tells Limine to use the Limine boot protocol (as opposed to multiboot).
- `path: boot():/boot/kernel` — path to the kernel ELF. `boot()` is Limine's shorthand for whichever partition it was loaded from.
- `module_path: boot():/boot/cp850-8x16.psf` — PSF1 bitmap font used by the framebuffer text renderer. Loaded into memory and passed via `module_request`.
- `module_path: boot():/boot/initramfs.cpio` — CPIO archive containing the initial filesystem (`/bin/sh`, `/bin/exectest`, etc.). Also loaded into memory and passed via `module_request`.
- `timeout: 5` — seconds to wait on the boot menu before selecting the default entry automatically.

## Linker script layout

`kernel/linker-scripts/x86_64.lds` controls how the kernel ELF is laid out in virtual memory. The kernel is linked at the top 2 GiB of the address space (`0xffffffff80000000`), which is where Limine expects a higher-half kernel.

```
OUTPUT_FORMAT(elf64-x86-64)
ENTRY(kmain)

. = 0xffffffff80000000;

.limine_requests  — Limine request structures (start marker, requests, end marker)
.text             — Executable code (page-aligned)
.rodata           — Read-only data, including exception message strings and font data
.note.gnu.build-id
.data             — Mutable globals
.bss              — Zero-initialised globals (COMMON symbols included)
/DISCARD/         — .eh_frame*, .note.note.* (stripped from the final binary)
```

Each major section is separated by a `ALIGN(CONSTANT(MAXPAGESIZE))` directive, which ensures that the kernel image can be mapped with correct permissions (read/execute for `.text`, read-only for `.rodata`, read/write for `.data`/`.bss`) without one section bleeding into another page.

The `.limine_requests` section is given its own `PT_LOAD` program header so Limine can locate the embedded request structs regardless of where the section lands relative to `.text`.

<Tip>
  Because `.bss` shares the `data` program header with `.data`, BSS is included in the loaded segment and zeroed by the ELF loader — the kernel does not need its own BSS-zeroing loop.
</Tip>

## kmain() init sequence

<Steps>
  <Step title="init_gdt()">
    Installs the six GDT entries (null, kernel code, kernel data, user data, user code, TSS) and writes the TSS descriptor. Must run first — many hardware operations require a valid segment environment.
  </Step>
  <Step title="init_idt()">
    Sets all 256 IDT gate entries to point at the appropriate `isr0`–`isr47` assembly stubs and loads the IDTR. Interrupts are not yet enabled, but the table is ready.
  </Step>
  <Step title="Base revision check">
    Calls `LIMINE_BASE_REVISION_SUPPORTED(limine_base_revision)`. If this returns `false`, `hcf()` is called immediately — the kernel cannot safely proceed with an incompatible bootloader.
  </Step>
  <Step title="init_display()">
    Retrieves the Limine framebuffer response and the PSF1 font module via `find_module_by_suffix(..., "cp850-8x16.psf")`. Constructs a `FrameBuffer` struct and calls `init_renderer()`. After this step `print()` works.
  </Step>
  <Step title="init_serial()">
    Configures COM1 at 38400 baud for debug output via `serial_print()`.
  </Step>
  <Step title="init_pmm()">
    Reads `memmap_request.response` and `hhdm_request.response`. Sets `hhdm_offset`, scans usable regions to find the highest physical address, allocates the bitmap and refcount array in the first region large enough to hold both, then marks all usable pages free. Reserves physical page 0.
  </Step>
  <Step title="init_vmm()">
    Reads CR3 and stores the kernel PML4 pointer. All user page tables copy the upper 256 entries from this root.
  </Step>
  <Step title="init_apic_timer()">
    Calls `init_apic()` to map LAPIC/IOAPIC and enable the APIC. Routes IRQ 1 → IDT vector 33 via `ioapic_set_irq(1, 0, 33)`. Calls `init_timer()` to calibrate the APIC timer using the PIT.
  </Step>
  <Step title="init_slab()">
    Initialises slab caches. `kmalloc()` and `kfree()` are now available for the rest of init.
  </Step>
  <Step title="init_scheduler()">
    Sets up the MLFQ queues, creates the idle process, and sets `current_process`.
  </Step>
  <Step title="Smoke tests">
    `run_slab_smoke_test()` exercises `kmalloc`/`kfree`. `run_wait_smoke_test()` creates two synthetic zombie processes and exercises `wait_reap_child()`. Both run before any real user process exists so they cannot race the scheduler.
  </Step>
  <Step title="mount_initramfs()">
    Finds the `initramfs.cpio` module via `find_module_by_suffix(..., "initramfs.cpio")` and calls `initramfs_init(address, size)` to parse and register the CPIO archive with the VFS.
  </Step>
  <Step title="init_keyboard()">
    Installs the PS/2 keyboard handler on IRQ 1 (which is now routed to IDT vector 33 by the IOAPIC).
  </Step>
  <Step title="init_syscalls()">
    Installs the syscall dispatch table so ring-3 processes can call into the kernel.
  </Step>
  <Step title="spawn_initial_processes()">
    Calls `create_user_process("/bin/exectest", ...)` and `create_user_process("/bin/sh", ...)`. Each call parses the ELF from initramfs, allocates a user page table, maps the segments, allocates a user stack, and enqueues the process on the MLFQ.
  </Step>
  <Step title="schedule()">
    Enters the scheduler. Under normal operation this never returns — the first call to `switch_task()` transfers the CPU into one of the newly created user processes. `kmain`'s stack frame is abandoned.
  </Step>
</Steps>

## PSF1 font loading

The kernel's framebuffer text renderer requires a PSF1 bitmap font before it can display anything. `init_display()` calls `find_module_by_suffix()` to scan the Limine module list for a file whose path ends in `cp850-8x16.psf`:

```c
static struct limine_file *find_module_by_suffix(
    struct limine_module_response *modules, const char *suffix)
{
    if (modules == NULL)
        return NULL;

    size_t slen = strlen(suffix);
    for (size_t i = 0; i < modules->module_count; i++) {
        struct limine_file *mod = modules->modules[i];
        size_t plen = strlen(mod->path);
        if (plen >= slen &&
            memcmp(mod->path + plen - slen, suffix, slen) == 0)
            return mod;
    }
    return NULL;
}
```

If no matching module is found, `init_display()` calls `hcf()` — the kernel cannot produce any output without the font and there is no point continuing.

## hcf() — halt-catch-fire

`hcf()` is the kernel's last-resort abort function. It simply loops forever executing `hlt`, keeping the CPU in the lowest-power halted state while preventing any further progress:

```c
static void hcf(void)
{
    for (;;) {
        asm("hlt");
    }
}
```

It is called in three circumstances during early boot:

- The Limine framebuffer response is missing (no display).
- The PSF1 font module is missing (renderer cannot initialise).
- `LIMINE_BASE_REVISION_SUPPORTED` returns false (incompatible bootloader).

<Warning>
  `hcf()` does **not** print a diagnostic message — by the time most of these checks run, the display may not yet be available. If aeryk appears to freeze immediately after power-on, check that `limine.conf` is present, the kernel ELF is at `boot():/boot/kernel`, and both modules are loadable.
</Warning>
